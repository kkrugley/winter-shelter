# SafePaws — UX/UI Redesign Handoff

**Передача разработчику (Claude Code):** низкополигональные wireframes всего сайта + UX-логика, основанные на аудите текущей версии.

---

## 0 · TL;DR для разработчика

Ты получаешь **структурный редизайн** сайта [safepaws.vercel.app](https://safepaws.vercel.app/). Работа состоит из двух частей:

1. **`audit/safepaws-audit.md`** — полный UX/UI-аудит текущего сайта: что сломано, почему и какие решения предлагаются.
2. **`wireframes/`** — интерактивный HTML-документ с низкополигональными (low-fi) wireframes всех 8 страниц нового сайта + 5 вариантов главной. Открывается в браузере как единое приложение с переключателем страниц.

**Важно:** это **wireframes, а не hi-fi макеты**. Цель — зафиксировать **структуру, архитектуру, UX-логику и иерархию контента**. Визуальный стиль (финальная палитра, типографика, иллюстрации, фото) — отдельный этап. Задача Claude Code: взять структуру из wireframes + рекомендации из аудита и реализовать это в целевом стеке с современным визуалом.

**Целевой стек** (из аудита, раздел «Технические рекомендации»): **Next.js 14 App Router + TypeScript + Tailwind CSS + shadcn/ui**. Весь контент — из Sanity CMS. SSR/ISR. Язык интерфейса — **русский** (с будущей возможностью добавить английский).

## 1 · Как пользоваться wireframes

1. Открой `wireframes/SafePaws Wireframes.html` в любом браузере.
2. Сверху — панель навигации по страницам (Home, Solutions, Product, Help, Stories, About, Download, Site map).
3. У страницы Home — 5 вариантов (вкладки A/B/C/D/E). На остальных страницах — по одному варианту.
4. Клавиша **T** — открывает панель Tweaks (акцентный цвет, плотность, аннотации).
5. Клавиша **A** — включает/выключает аннотации дизайнера (пояснения прямо в макетах).

Страницы рендерятся из отдельных JS-модулей в `wireframes/pages/`. Стили — `wireframes/styles/wireframe.css`. Шрифт — Caveat (sketchy) + Inter (для метаданных).

## 2 · Карта сайта и архитектура

```
/                    Home — развилка для пользователя (3 пути: сделать / поддержать / узнать)
/solutions           Каталог всех решений (Cozy, Family, PurrTap + будущие)
/solutions/[slug]    Страница продукта (галерея, скачать, материалы, FAQ)
/help                Как помочь — 9 путей по уровню вовлечения
/stories             Истории с карты + пользовательские
/stories/add         Форма добавления своей истории
/about               Миссия, автор, timeline проекта
/download            Мастер скачивания чертежей (3 шага)
```

**Принципы архитектуры** (см. страницу «Site map» в wireframes):

- **Один путь — одна цель.** Каждая страница отвечает на один вопрос пользователя.
- **Продукты равноправны.** Cozy, Family, PurrTap живут в общем каталоге — никаких «основной / вспомогательный».
- **CTA = действие, а не «узнать больше».** Глагол + объект: «Скачать чертёж», «Поделиться историей».
- **Эмоция + утилита.** Главная должна и вовлекать, и направлять — не только одно из двух.

## 3 · Home: выбранное направление

В исследовании было 5 вариантов главной. Для реализации **рекомендую вариант A (Трёхпутевая развилка)** как базу + элементы из C (эмоциональный блок статистики) и E (мини-карта историй в нижней секции).

### Структура Home (вариант A + рекомендованные дополнения):

1. **Hero**
   - Заголовок: «Каждая лапа заслуживает безопасного дома» (или аналогичный, 4-7 слов, эмоциональный но не слезливый).
   - Подзаголовок: 1 предложение о сути проекта — открытые чертежи защитных решений для бездомных животных.
   - **Три большие кнопки-карточки** (главная развилка):
     - 🔨 **Сделать своими руками** → `/solutions`
     - ❤️ **Поддержать проект** → `/help`
     - 📖 **Узнать о проблеме** → `/about` (или якорь на блок ниже)
   - Счётчик под кнопками: «47 чертежей скачано · 12 городов · 340 построено».

2. **Блок «Проблема»** (короткий, эмоциональный, из варианта C)
   - 3 факта с крупными цифрами (из данных проекта).
   - Фото/иллюстрация животного в холоде.
   - CTA: «Узнать больше →» ведёт в About.

3. **Блок «Решения»** (превью каталога)
   - 3 карточки: Cozy House, Family Den, PurrTap.
   - **PurrTap должен стоять на равных** с остальными (важно — сейчас он потерян, см. аудит).
   - CTA «Все решения →» ведёт в `/solutions`.

4. **Блок «Как помочь»** (превью 3 путей из 9)
   - «Построить», «Рассказать», «Поддержать» — как карточки с иконкой + 1 строкой описания.
   - CTA «Все способы помочь →» ведёт в `/help`.

5. **Блок «Истории»** (мини-карта + 3 карточки)
   - Карта с точками (где уже построены укрытия).
   - 3 последние истории как карточки.
   - CTA «Все истории →» ведёт в `/stories`.

6. **Footer**
   - Колонки: Навигация / Контакты / Соцсети / Юридическое.
   - Крупный CTA «Скачать первый чертёж» как финальная точка.

### Что НЕ делать на главной:
- ❌ Длинные абзацы текста (это страница-маршрутизатор, не статья).
- ❌ «Узнать больше» без контекста — всегда глагол + объект.
- ❌ Скрывать PurrTap или презентовать его как вспомогательный.
- ❌ Автокарусель без пауз.

## 4 · Детали по страницам

### 4.1 · Solutions (`/solutions`)

**Задача:** показать все продукты в едином каталоге с фильтрами.

**Структура:**
- Верх: breadcrumbs + H1 «Все решения» + счётчик.
- Фильтры слева (sidebar на desktop, collapsible drawer на mobile):
  - Тип животного: кошки / собаки / универсальное
  - Сезон: зима / всё время
  - Сложность сборки: легко / средне / сложно
  - Инструменты: CNC / лобзик / только руки
  - Материал: фанера / картон / пластик
- Сетка карточек продуктов (3 кол. на desktop, 2 на tablet, 1 на mobile).
- Карточка: изображение + название + 1 строка описания + бейджи (сложность, сезон) + кнопка «Подробнее».
- Внизу: таблица сравнения всех продуктов (для тех, кто не определился).

### 4.2 · Product page (`/solutions/[slug]`)

Пример — Cozy House. Структура одинаковая для всех продуктов.

**Секции сверху вниз:**
1. **Hero:** галерея (4-5 фото) + справа: название, сложность, время сборки, сезон, большая кнопка «Скачать чертёж».
2. **Спецификации:** размеры, вес, материалы (табличка).
3. **Калькулятор материалов:** пользователь вводит количество — получает список закупки.
4. **Инструкция сборки:** шаги с фото (аккордеон).
5. **Галерея примеров:** фото построенных домиков от волонтёров.
6. **FAQ:** частые вопросы по сборке и использованию.
7. **Связанные продукты:** 2-3 карточки.

### 4.3 · Help / Get Involved (`/help`)

**Задача:** показать все способы участия — не только деньги.

**Структура:**
- Hero: «Как ты можешь помочь» + фильтр «что у тебя есть?» (чипсы: время / навыки / материалы / деньги / соцсети).
- Сетка из **9 карточек** (по результатам фильтра подсвечиваются релевантные):
  1. Построить укрытие своими руками
  2. Организовать сбор материалов
  3. Провести мастер-класс в школе/ТЦ
  4. Снять и выложить видеоотчёт
  5. Перевести на языки (помощь переводчика)
  6. Рассказать в соцсетях
  7. Помочь с разработкой (код, дизайн)
  8. Финансовая поддержка
  9. Стать амбассадором в своём городе
- Каждая карточка: иконка + заголовок + 2 строки описания + кнопка «Начать».

### 4.4 · Stories (`/stories`)

**Задача:** социальное доказательство + карта охвата.

**Структура:**
- Hero: карта России/мира с точками (построенные укрытия). Hover = превью истории.
- Фильтры: город / продукт / дата.
- Сетка карточек историй: фото + автор + город + дата + 2 строки цитаты + «Читать».
- CTA-блок: «Построил? Поделись» → `/stories/add`.

### 4.5 · About (`/about`)

**Структура:**
- Hero: миссия проекта (1 абзац крупным шрифтом).
- Блок «Зачем»: проблема в цифрах.
- Блок «Автор»: фото + биография + цитата.
- Timeline проекта: ключевые вехи.
- Статистика: live-счётчики (чертежей, городов, партнёров).
- CTA: «Присоединиться» → `/help`.

### 4.6 · Download flow (`/download` или модалка с `/solutions/[slug]`)

**Задача:** превратить скачивание в осмысленный мини-визард.

**3 шага:**
1. **Выбор модели** (если пришёл с общего `/download`) или подтверждение.
2. **Выбор материала/размера** — влияет на чертёж.
3. **Формат файла** (PDF / DXF / STL для CNC) + email для отправки ссылки (опционально, для аналитики использования и feedback).

После скачивания — экран благодарности с CTA: «Расскажи, когда построишь» → `/stories/add`.

## 5 · Design tokens (стартовая точка)

**Это для wireframes.** Финальная палитра — отдельная задача дизайнера. Но для быстрого старта Claude Code:

```css
/* Используй как базу, потом подстрой под бренд */
--color-bg: #FDFBF7;        /* тёплый off-white, не чисто белый */
--color-fg: #1A1917;        /* тёплый чёрный */
--color-muted: #6B6862;
--color-accent: #D97757;    /* тёплый коралловый — можно заменить */
--color-accent-soft: #FBE8DE;

--font-display: "Caveat", cursive;    /* ТОЛЬКО для wireframes */
--font-body: "Inter", -apple-system, sans-serif;
--font-heading: TBD — подобрать под бренд;

--radius-sm: 6px;
--radius-md: 12px;
--radius-lg: 20px;

--space: 4px;               /* базовая единица, умножать */
```

**Для hi-fi:** подобрать гарнитуру заголовков (рекомендую что-то тёплое-гуманистическое — **Fraktur**, **Söhne**, **General Sans**, или **Instrument Serif** для заголовков + геометрический sans для body). **Избегать Inter/Roboto** — они уже ощущаются generic.

## 6 · Поведение и интерактивность

- **Все карточки** — hover: лёгкий lift (`translate-y-[-2px]` + тень).
- **CTA-кнопки** — два уровня: primary (заполненная, акцент) и secondary (контур).
- **Навигация** — sticky top, на mobile — hamburger.
- **Фильтры на Solutions/Help** — sync с URL query params (`?tool=cnc&difficulty=easy`), чтобы можно было шарить.
- **Карта Stories** — используй Leaflet или Mapbox, точки кластеризовать.
- **Изображения** — Next.js `<Image>`, AVIF/WebP, lazy loading, blur placeholder.
- **Тёмная тема** — опционально, но желательно; система `prefers-color-scheme`.

## 7 · SEO и метрики

Из аудита (раздел «SEO»):

- Уникальный `<title>` и `meta description` для каждой страницы.
- Open Graph + Twitter Card на всех продуктах и историях.
- `sitemap.xml` генерировать из Next.
- JSON-LD структурированные данные:
  - `Organization` на главной
  - `Product` на страницах продуктов
  - `Article` на историях
- Подключить **Plausible** или **Umami** (privacy-friendly аналитика, не GA).

Ключевые события для аналитики:
- Клик на «Скачать чертёж»
- Завершение download flow
- Отправка формы «Добавить историю»
- Клик на CTA в секции «Помочь»

---

## 8 · Доступность (a11y)

- Все CTA — `<button>` или `<a>` с видимым фокусом.
- Контраст ≥ 4.5:1 для текста, ≥ 3:1 для UI.
- Альт-текст для всех изображений животных (не «фото кошки», а описание ситуации).
- Навигация клавиатурой: Tab-порядок логичный, никаких `tabindex > 0`.
- `prefers-reduced-motion` — отключать большие анимации.

## 9 · Что НЕ включено в этот handoff (явно для ясности)

- ❌ Готовые hi-fi макеты (Figma).
- ❌ Финальная палитра и шрифтовая система.
- ❌ Иллюстрации / фотоконтент.
- ❌ Копирайт (тексты) — в wireframes только placeholder/направление.
- ❌ Backend и CMS-схема.

Это осознанно — чтобы разработчик не ограничивался одним визуальным решением, а имел структурную свободу. Копирайт и визуал — следующий круг работы.

## Вопросы?

Всё, что непонятно в структуре или логике — сверяться сначала с аудитом (`audit/safepaws-audit.md`), потом с wireframes. Если между ними конфликт — побеждает **аудит** (он первичный документ).

**Не копировать структуру HTML из wireframes дословно** — они написаны на ванильном JS для быстрой итерации. Цель — воссоздать **логику и визуальную иерархию** в чистом Next.js + React.
