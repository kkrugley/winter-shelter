## 3. КАСКАД И КЛАССИФИКАЦИЯ ПРОБЛЕМ

### 3.1 UX‑проблемы

| Приоритет | Проблема | Влияние |
| --------- |----------|---------|
| 🔴 Крит | Отсутствие PurrTap на сайте | Потеря 50 %+ потенциальных помощников |
| 🔴 Крит | Нет визуализации продуктов | Пользователь не понимает, что скачивает |
| 🟡 Выс | Фокус на «чертежах», а не на помощи животным | Низкая эмоциональная вовлечённость |
| 🟡 Выс | Нет storytelling про бездомных | Слабая мотивация к действию |
| 🟢 Сред | Дублирование CTA‑кнопок | Пользователь теряется |

### 3.2 Продуктовые проблемы

| Проблема | Описание |
|----------|----------|
| Нет единого каталога | Продукты разбросаны по разным страницам |
| Масштабируемость = 0 | Добавление нового продукта = ручная правка всех страниц |
| Нет сравнения продуктов | Пользователь не понимает, какой выбрать |
| Нет калькулятора материалов | «2 листа фанеры» – недостаточно точно |
| Нет галереи реализаций | Только 3 карточки |

### 3.3 Технические проблемы

| Проблема | Последствия |
|----------|------------|
| Чистый HTML/CSS/JS | Сложность поддержки |
| Ручная локализация | Риск рассинхронизации переводов |
| Дублирование кода | Хедер/футер копируется в каждый файл |
| Отсутствие сборки | Нет оптимизации, минификации |
| Bootstrap Icons (~2000 SVG) | Лишний вес репозитория |

```

    ├── Shelters (укрытия)
```

### 5.2 Структура страниц

| Страница | URL | Назначение |
|----------|-----|------------|

| Solutions | `/solutions` | Каталог всех продуктов с фильтрами |
| Product | `/solutions/[slug]` | Детальная страница продукта |
| Get Involved | `/help` | Способы помочь (сборка, поилка, донат, шеринг) |
| Stories | `/stories` | Карта и истории реальных домиков |
| About | `/about` | Миссия, автор, статистика, контакты |
| Download | `/download/[file]` | Прямая загрузка файлов |

### 5.3 UX‑логика нового сайта

```mermaid
flowchart TD
  A[Пользователь заходит] --> B[HERO: проблема]
  B --> C[SOLUTIONS: каталог]
  C --> D[HOW TO HELP: варианты участия]
  D --> E[STORIES: реальные истории]
  E --> F[Следующие шаги (CTA)]
```

### 5.4 Контент‑логика (Storytelling)

1. **Проблема** – почему важно  
2. **Решение** – как продукт помогает  
3. **Детали** – материалы, размеры, процесс  
4. **Действие** – скачать / узнать больше / поделиться

Пример для PurrTap:

- **Проблема**: «Каждый день бездомные животные пьют из грязных луж»  
- **Решение**: PurrTap — поилка, которую может пополнить любой прохожий  
- **Действие**: «Установить в своём дворе» + инструкция

## 10. ЗАКЛЮЧЕНИЕ

Текущий SafePaws — теплый, но устаревший проект, решающий только «скачать чертеж», но не вовлечённый в реальную помощь животным.

**Новый сайт должен**:

1. ✅ Показать проблему (бездомные животные зимой)  
2. ✅ Предложить решения через каталог (Shelters + PurrTap + Future)  
3. ✅ Упростить выбор с визуализацией & сравнением  
4. ✅ Вдохновлять: истории, карта, сообщество  
5. ✅ Масштабироваться: добавление продуктов без разработки

*Главная метрика успеха*: количество установленных домиков и поилок в реальном мире, а не количество скачиваний.
